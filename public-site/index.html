Hobby Project, Real Ops Discipline

Build your own self-hosted endpoint and stream lab

Beagle OS is developed as a hobby project, but with serious operational rigor. The stack focuses on one clear path: standalone host virtualization, managed endpoint media, and reproducible stream validation.

What this project is

Standalone first

No hosted control-plane dependency required. You run host, VMs, endpoint media and stream workflows in your own environment.

What this project is not

No hosted broker dependency

Beagle OS is intentionally focused on a narrow operating model and avoids old multi-variant product assumptions.

Platform pillars

Everything in the repository and docs maps back to these four operating pillars.

HOST

Standalone host stack

KVM/libvirt host runtime with Beagle control services, health checks and reproducible setup scripts.

VM

VM lifecycle control

Provision, start, stop and inspect VMs through WebUI and API with audited operations.

EP

Endpoint media

Generate VM-specific endpoint USB media for deterministic enrollment and assignment behavior.

STRM

Stream validation

Track first-stream readiness and runtime stability as explicit release and operations gates.

Core workflows

Start with a clean host, validate lifecycle behavior, then scale endpoint operations.

Workflow 1

Clean install to healthy host

Install host services, validate health checks, and confirm WebUI control path before creating VMs.

Workflow 2

VM create and stream readiness

Provision an Ubuntu Beagle VM, verify guest readiness and complete first lifecycle smoke tests.

Workflow 3

Endpoint media and assignment

Generate media for one VM, boot endpoint, verify enrollment and confirm first stream session health.

Project values

The project remains hobby-driven, but quality gates are treated like production engineering constraints.

Reproducible fixes

Live hotfixes only count when changes are committed and testable in the repository.

Explicit evidence

Release promotion requires clean-install and runtime evidence, not only passing local smoke tests.

Narrow scope

The active provider path is Beagle KVM/libvirt. Scope creep into old system assumptions is avoided.
