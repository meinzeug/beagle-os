Operate Beagle OS from the WebUI

The Beagle Web Console is the primary operator surface for a standalone Beagle host. Use it to validate a fresh install, create VMs, follow provisioning, prepare thin-client media, manage endpoints, inspect streams, handle updates, and collect evidence for support.

First login and install validation

  1. Open the host URL after installation. A fresh host should expose the Web Console through nginx and the Beagle Control Plane.
  2. Complete the initial admin/onboarding flow if the host has no configured administrator yet.
  3. Open the health/install checks view and verify that Control Plane, nginx, libvirt, downloads, repo update status, and hosted artifacts are green.
  4. If a check fails, inspect the linked detail first. Do not continue to VM provisioning while required host services are red.
ssh srv1.beagle-os.com
/opt/beagle/scripts/check-beagle-host.sh
systemctl --failed --no-pager

Create a VM

  1. Open Virtualization and choose the Ubuntu Beagle desktop template unless you intentionally need another image.
  2. Set CPU, memory and disk within the host capacity shown by the WebUI. Leave host RAM and CPU headroom for libvirt, nginx, control-plane workers and artifact refresh jobs.
  3. Choose the Beagle bridge for networking on standalone hosts.
  4. Start provisioning and keep the VM detail page open. The expected path is create, autoinstall boot, firstboot, guest agent, desktop services, stream readiness.
  5. If provisioning fails, copy the exact WebUI error and check the VM event log before deleting artifacts manually.

VM detail workflow

  • Summary: power state, node, IP address, guest agent state, provisioning phase and recent actions.
  • Console: noVNC access for installation and firstboot observation.
  • Config: CPU, memory, boot, firmware, network, storage and Beagle runtime options.
  • Downloads: VM-specific USB installer/live media for assigned endpoints.
  • Stream: BeagleStream target, allocation, WireGuard requirement and health events.
  • Backup: VM-scope backup runs, restore evidence and retention policy.
  • Audit: action history for create, start, stop, delete, stream and backup operations.

Endpoint and thin-client flow

  1. Create or select a VM and wait until the VM has a stable runtime profile.
  2. Open the VM downloads view and generate a VM-specific Linux or Windows USB writer script.
  3. Write the media, boot the thin client, and let enrollment apply the control-plane URL, token, WireGuard state and stream target.
  4. Use the Endpoints page to confirm last check-in, assigned VM, tunnel state and stream-client launch state.
  5. Use Streams to verify that the desktop is allocated through the BeagleStream path and not through a manual fallback.

Updates, releases and channels

Use the update panel to see installed version, remote version, installed commit, remote commit, update channel and artifact build status. Stable follows published release tags. Rolling follows the current repository branch and is for validation work, not a customer install baseline.

  • Use stable for clean-install evidence and customer-facing validation.
  • Use rolling only to validate a repo fix before the next release is published.
  • Do not rely on a live hotfix unless the same change is committed and pushed.
  • After an artifact refresh, confirm `beagle-downloads-status.json` and hosted files match `VERSION`.
