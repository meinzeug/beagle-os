Endpoint OS

Endpoint runtime built for managed streaming

The endpoint image is optimized for deterministic enrollment and stream startup, not as a general-purpose desktop. Keep endpoint behavior tightly aligned with assigned VM and policy state.

Image variants

  • Live runtime media for fast validation and field boot.
  • Installer media for persistent endpoint installations.
  • VM-specific script-generated media when assignment should be pre-bound.

Boot and enrollment sequence

  1. Endpoint boots and initializes runtime services.
  2. Identity and enrollment metadata are loaded from generated media profile.
  3. Control plane handshake validates assignment and policy.
  4. WireGuard or approved transport state is brought up.
  5. Stream client starts against the assigned VM target.

Operational checks

  • Endpoint appears in WebUI with current heartbeat timestamp.
  • Assigned VM matches expected target and profile metadata.
  • Stream process is healthy and reconnect behavior is deterministic.
  • Audio, display and optional USB bridge state match policy.

Update behavior

Endpoint updates should be rolled out in controlled groups. Validate one canary endpoint first, then move to wider rollout. Keep rollback media available for field recovery.

  • Do not mix unstable host changes with broad endpoint rollout.
  • Document tested kernel/runtime combination for each release wave.
  • Capture before and after evidence for stream startup and reconnect.
