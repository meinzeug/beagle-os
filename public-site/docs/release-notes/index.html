Release Notes

Current release policy for Beagle OS 8.x

This page tracks release expectations for the standalone Beagle host. Stable release promotion requires clean-install evidence and runtime gate validation, not only rolling host updates.

Channel model

Stable

Published artifacts intended for clean installs and production-like operations. Promotion requires validation matrix evidence.

Rolling

Continuous integration path for live validation and early bugfix verification. Not a substitute for clean-install release proof.

Release promotion gates

  • Clean host install from release artifact succeeds.
  • Host health checks pass directly after install.
  • WebUI login, VM create, VM delete and endpoint path are verified.
  • BeagleStream first session succeeds with expected runtime health.
  • Security and backup baseline checks are complete.

Known risk classes

Risk classTypical symptomRequired response
Provisioning regressionsFresh VM creation failsPatch in repo with regression test before release
Artifact mismatchHosted files do not match version metadataRebuild and re-publish artifacts with integrity checks
Endpoint enrollment driftWrong VM mapping or missing policyFix profile generation path and revalidate media
Stream runtime driftSession fails after updateRollback or patch and repeat end-to-end validation

Operator release checklist

  1. Confirm installed and remote version metadata alignment.
  2. Run host health checks and archive outputs.
  3. Run VM lifecycle smoke and endpoint stream smoke.
  4. Validate backups and restore metadata path.
  5. Document final evidence before announcing release.
