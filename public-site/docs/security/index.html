Security

Scoped trust with explicit operational evidence

Beagle OS secures host, VM and endpoint operations through minimal exposure, strict identity scopes, reproducible configuration and audit-first workflows.

Trust boundaries

  • Host control plane boundary: orchestrates actions and policy with privileged services.
  • Provider runtime boundary: virtualization actions through contracts with explicit validation.
  • Endpoint boundary: enrolled runtime with scoped identity and managed tunnel path.
  • Public site boundary: static documentation and downloads, no control-plane authority.

Identity and token model

  • Use least-privilege API tokens with clear scope and expiration policy.
  • Treat endpoint enrollment credentials as short-lived bootstrap material.
  • Rotate tunnel keys and scoped secrets on schedule and after incident events.
  • Store key material with strict owner and permission checks.

Network exposure model

The preferred model is no public endpoint ports. Endpoint traffic should use approved encrypted paths, typically WireGuard-backed routes and authenticated reverse tunnels for device forwarding.

  • Expose only required host entry points.
  • Keep management and cluster traffic restricted to trusted networks.
  • Reject direct endpoint public listeners unless explicitly approved.

Host hardening baseline

  1. Run health and security checks after install and every update window.
  2. Verify firewall baseline and intended open port set.
  3. Validate TLS certificates and reverse proxy settings.
  4. Track package and artifact provenance with version metadata.
  5. Review audit/event logs for suspicious operational patterns.
